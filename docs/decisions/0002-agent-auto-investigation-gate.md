# 0002. 조사 에이전트 자동 운영 승격 — 게이트 판정

- 상태: 채택 (2026-07-27)
- 결정자: 신현수

## 배경

인시던트가 열리면 조사 에이전트가 검사 결과를 스스로 조사해 원인을 7유형으로 분류하고
조치를 제안한다. 판단 일부를 LLM이 하므로, "돌아간다"와 "믿고 자동으로 돌려도 된다"는
다른 문제다. 그래서 구현 전에 통과 기준(게이트)을 먼저 정하고, 평가셋을 dev/test로 나눠
**test는 튜닝에 한 번도 쓰지 않고 마지막에 딱 한 번 채점**하기로 했다.

## 결정

**게이트 4종을 모두 통과했으므로 자동 조사를 운영 기본 동작으로 유지한다.**

측정: 2026-07-27, test 83건 1회 채점 (`python -m aim_worker.agent.llm_eval --split test`).

| 게이트 | 기준 | 실측 | |
|---|---|---|---|
| G1 분류 정확도 | test ≥ 95% (오류 ≤ 4) | **100.0%** (83/83) | 통과 |
| G2 위험 방향 오분류 | 파손 → 정상류 0건 | **0건** | 통과 |
| G3 비용·지연 | rule-first 라우팅, LLM p50 < 20s | LLM 대상 **28/83**, p50 **2.7s**, p95 4.0s, 83건 **$0.059** | 통과 |
| G4 폴백·추적 | 규칙 폴백 동작, 생성 주체 기록 | 폴백 **0건**, generator에 rule/llm 기록 | 통과 |

규칙 베이스라인 대비 churn은 고침 6건 / 망가뜨림 0건, 무단 도구 시도 0건, 에스컬레이션
0회(Haiku 단독으로 충분)였다.

## 이 수치가 증명하는 것과 못 하는 것

- **증명한다**: 라우팅·폴백·비용 구조가 설계대로 동작하고, 규칙이 못 가르던 경계
  (지연 판정, 스테일 판정)를 LLM이 회귀 없이 개선한다.
- **증명하지 못한다**: test 83건은 전부 합성 케이스다. 실측 사고 5건은 의도적으로 dev에만
  두었기 때문에(트레이스를 보고 코드를 고친 데이터라 test에 섞이면 채점이 낙관 편향된다),
  이 100%는 **합성 분포 안에서의 상한**이지 실운영 정확도가 아니다.

실운영 근거는 별도로 lab 실험대(`infra/lab/`)의 도그푸딩이 담당했고, 네 유형을 실제
장애로 재현해 모두 정판정을 확인했다 — 응답 지연, 서비스 다운, UI 회귀, 시나리오 스테일.
그 과정에서 결함 4건(없는 증거 단정, 재검사 시나리오 누락, 인시던트 해소 플랩, 빈 증거
소실)을 찾아 고쳤다. **게이트를 통과시킨 것은 합성 점수가 아니라 이 사이클이다.**

## 남은 한계

- **SSL 무효**는 운영에서 위조할 수 없어 도그푸딩하지 못했다 — 합성 케이스로만 검증된다.
- **프런트 성능 회귀**는 실측 사고(다운사이징) 재현이 curated로 dev에 있을 뿐,
  운영 재현은 하지 않았다.
- 스크린샷 판독기가 없어 `failing_page_rendered_ok`는 여전히 수집되지 않는다. 이동 흔적
  판독기가 그 공백을 상당 부분 메우지만, 렌더 파손 여부를 직접 보는 신호는 아니다.

## 정직성 메모: 순서가 계획과 달랐다

원래 계획은 "게이트 통과 전에는 수동 트리거 전용, 통과 후 자동 연결"이었다. 실제로는 W4에서
인시던트 훅을 연결할 때 플래그 없이 자동 트리거가 바로 켜졌고, 게이트 측정은 그 뒤에 이뤄졌다.
결과적으로 기준을 통과했으므로 현재 동작을 유지하지만, **검증보다 배선이 앞섰다는 사실은
기록해 둔다.** 다음에 판단이 개입하는 기능을 붙일 때는 플래그로 실제로 잠가야 한다.

## 결과

- 자동 조사는 인시던트가 새로 열릴 때만 트리거되고, 프로젝트당 30분 쿨다운이 걸린다.
- 조사는 읽기 전용 도구 6종 + 재검사 1종만 쓸 수 있고, 설정·베이스라인 변경 수단이 없다.
- LLM 실패 시 규칙 폴백으로 결론을 내며, 생성 주체는 `agent_investigations.generator`에 남는다.
- 평가셋을 바꾸면 test 구성이 달라지므로, 최종 채점은 평가셋 변경이 끝난 뒤에만 다시 한다.
